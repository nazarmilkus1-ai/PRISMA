# PRISMA-агент (автономный разработчик)

Живёт **только** в топике админ-группы (chat `-1004365081749`, thread `1469`), работает 24/7 сам.

- Цикл каждые ~10 мин: читает сообщения людей (админы = приоритет, остальные = предложения), память, цель → работает инструментами → итог в журнал.
- Своя цель, свой план, % готовности и % «работает» (по CI). Менять ожидания и идеи можно.
- Код: только ветки `agent/*`, атомарные коммиты через Git Data API, PR открывается сам. Нельзя `.github/`, env, секреты.
- Каждый час отчёт в топик + кнопка **✅ Слить** (только владелец или `AGENT_MERGE_ADMIN_IDS`; CI должен быть зелёным; миграции БД не сливаются кнопкой; BLOCK ревьюера — только владелец «Слить всё равно»).
- Память: закреплённое ядро + полнотекстовый поиск + ежедневное сжатие старых заметок.
- Второй ИИ (ревьюер, ключ `AI_API_KEY_ADMIN`) читает diff и даёт OK/RISKS/BLOCK.
- Команды админов в топике: `/agent` (панель), `/task <что сделать>` (задача админа: берётся первой, цикл стартует в течение минуты), `/ideas`, `/agent_pause`, `/agent_resume`, `/agent_report`; `/agent_help` — справка для всех.
- Кнопки-панель под живым статусом, отчётом и списками: 📋 Очередь · 💡 Идеи · ⏸ Пауза · ❓ Помощь. Идеи агента: «▶ N» ставит идею задачей, «✖ N» убирает.
- Как агент работает над задачей: план из 3–6 шагов → `step_done` по ходу → прогресс считается по шагам (не «на глаз»); ничего не коммитится, если в файлах синтаксическая ошибка Python, битый JSON или нарушено архитектурное правило (прямой CRUD в `bot/db`, `bot/services`).
- Инструменты: `repo_search` — регулярка по всему коду из zip-архива ветки (кэш 10 мин), `repo_read start/end` — большой файл кусками, `ci_status` — при красном CI вместе с выдержкой из лога упавшей проверки. Красный PR агент чинит первым (до 3 попыток на PR), потом задачи админов, потом свои идеи.
- Когда задача готова и тесты зелёные, агент сразу присылает карточку «🔔 Готова новая задача» с кнопками Принять / Отклонить.
- На обращение к агенту (ответ на его сообщение, упоминание или вопрос админа с «?») он коротко отвечает простыми словами по текущему состоянию; просьба админа превращается в задачу в очереди.

Env (Render): `AI_API_KEY_AGENT`, `AI_MODEL_AGENT` (список через запятую), `AI_MODEL_REVIEWER`, `AGENT_ENABLED`, `AGENT_MERGE_ADMIN_IDS`, `AGENT_CHAT_ID`, `AGENT_THREAD_ID`, `AGENT_DM_COPILOT=1` (вернуть старого агента в ЛС).
