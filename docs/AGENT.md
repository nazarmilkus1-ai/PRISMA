# PRISMA-агент (автономный разработчик)

Живёт **только** в топике админ-группы (chat `-1004365081749`, thread `1469`), работает 24/7 сам.

- Слияния, обновление веток, пересборка PR и карточки «Нужно ваше решение» идут отдельным фоновым циклом раз в ~100 секунд (не ждут окончания долгого цикла работы) и в конце каждого цикла.
- Цикл: сразу один за другим (пауза `BUSY_CYCLE_SECONDS`=150 с, пока есть что делать; в режиме автослияния — всегда), на паузе или при выключенном автослиянии без работы — раз в ~10 мин: читает сообщения людей (админы = приоритет, остальные = предложения), память, цель → работает инструментами → итог в журнал.
- Своя цель, свой план, % готовности и % «работает» (по CI). Менять ожидания и идеи можно.
- Код: только ветки `agent/*`, атомарные коммиты через Git Data API, PR открывается сам. Нельзя `.github/`, env, секреты.
- Каждый час отчёт в топик + кнопка **✅ Слить** (только владелец или `AGENT_MERGE_ADMIN_IDS`; CI должен быть зелёным; миграции БД не сливаются кнопкой; BLOCK ревьюера — только владелец «Слить всё равно»).
- Память: закреплённое ядро + полнотекстовый поиск + ежедневное сжатие старых заметок.
- Второй ИИ (ревьюер, ключ `AI_API_KEY_ADMIN`) читает diff и даёт OK/RISKS/BLOCK.
- Команды админов в топике: `/agent` (панель), `/task <что сделать>` (задача админа: берётся первой, цикл стартует в течение минуты), `/ideas`, `/agent_auto on|off`, `/agent_pause`, `/agent_resume`, `/agent_report`; `/agent_help` — справка для всех.
- Кнопки-панель под живым статусом, отчётом и списками: 📋 Очередь · 💡 Идеи · ⏸ Пауза · ❓ Помощь. Идеи агента: «▶ N» ставит идею задачей, «✖ N» убирает.
- Как агент работает над задачей: план из 3–6 шагов → `step_done` по ходу → прогресс считается по шагам (не «на глаз»); ничего не коммитится, если в файлах синтаксическая ошибка Python, битый JSON или нарушено архитектурное правило (прямой CRUD в `bot/db`, `bot/services`).
- Инструменты: `repo_search` — регулярка по всему коду из zip-архива ветки (кэш 10 мин), `repo_read start/end` — большой файл кусками, `ci_status` — при красном CI вместе с выдержкой из лога упавшей проверки. Красный PR (или PR с BLOCK ревьюера) агент чинит первым (до 4 попыток на PR; потом пересобирает задачу заново), потом задачи админов, потом свои идеи.
- **Автономный режим** (по умолчанию, `AGENT_AUTO_MERGE=1`; выключатель `/agent_auto on|off` для главных админов, состояние хранится в `agent_state.auto_merge`): агент сам сливает свои готовые PR, когда все автопроверки зелёные (и их не ноль) и ревьюер не поставил BLOCK — те же проверки, что у кнопки «Принять». Не чаще одного слияния в 15 минут (каждое слияние перезапускает бота) и не более `MAX_AUTO_MERGES_PER_DAY`=60 в сутки. После слияния в топик приходит сообщение «🚀 Принято и слито — сам» с кнопкой «↩ Откатить»: она ставит агенту отдельную задачу вернуть файлы из коммита до слияния.
- Что агент делает сам с застрявшими PR: красные автопроверки и BLOCK — правит до 4 раз; PR с конфликтом с основной веткой — сначала «Update branch», при настоящем конфликте закрывает PR и ставит себе задачу «Переделать: …» на свежем коде (до 2 переделок на задачу, потом урок в память и отказ от задачи).
- Дневной лимит ИИ: если провайдер отвечает «Daily free-tier limit…», агент запоминает модель как исчерпанную до времени обновления, переходит на следующую из `AI_MODEL_AGENT`, а когда не осталось ни одной — один раз пишет в топик и до обновления лимита не пишет код. Слияния, обновление веток и пересборка PR при этом идут как обычно (им ИИ не нужен). `/agent_resume` снова пробует ИИ сразу. Чтобы не упираться в лимит, добавьте в `AI_MODEL_AGENT` ещё модели или ключ без дневного лимита.
- Защита от потери кода: коммит, после которого существующий файл (от 40 строк) становится короче чем на 30% или удаляется, отклоняется ещё до GitHub (модель увидела только начало файла и прислала его обратно). PR, который в основном удаляет код или тесты (≥150 строк и в 2 раза больше добавленного, или один файл −80 строк, или тестов удалено больше, чем добавлено), агент не сливает и не «чинит», а закрывает и пересобирает точечными правками (`edit`); задачу от админа с таким PR оставляет вам.
- Только человек решает (карточка «🔔 Нужно ваше решение» с кнопками Принять / Отклонить): правки кода самого агента (`bot/services/agent/`, `handlers/agent_topic.py`), миграции БД (`supabase/migrations/`), инфраструктура и зависимости (`.github/`, `scripts/`, `requirements.txt`, `package.json`, `Dockerfile`, `render.yaml`, `bot/main.py`, `bot/config*`) и код банов/наказаний (`ban_review`, `moderation`, `admin_actions`, `automod`). Выключение автослияния возвращает ручной режим: каждая готовая задача приходит карточкой «🔔 Готова новая задача».
- На обращение к агенту (ответ на его сообщение, упоминание или вопрос админа с «?») он коротко отвечает простыми словами по текущему состоянию; просьба админа превращается в задачу в очереди.

Env (Render): `AI_API_KEY_AGENT`, `AI_MODEL_AGENT` (список через запятую), `AI_MODEL_REVIEWER`, `AGENT_ENABLED`, `AGENT_AUTO_MERGE`, `AGENT_MERGE_ADMIN_IDS`, `AGENT_CHAT_ID`, `AGENT_THREAD_ID`, `AGENT_DM_COPILOT=1` (вернуть старого агента в ЛС).
Рекомендация: включить branch protection на `PRISMA`.
